## 首版验收方法

以下数值是待实测的工程目标。M0 记录参考板、屏幕刷新率、系统镜像和采样方法。在真机上用固定输入语料与可重复触摸脚本采集，按场景报告 P50/P95 与失败数。

| 指标 | 初始目标与测法 |
| --- | --- |
| 按下反馈 | 从触摸事件到可见按下反馈，P95 ≤ 50 ms。应用打点配合高帧率录像校验 |
| 中文候选 | 热启动时，从按键事件到当前代次的第一页本地候选可见，P95 ≤ 80 ms。至少采样 200 次含短词、整句及快速退格 |
| 拉起键盘 | 已加载引擎及面板资源后，从字段请求显示到可接收触摸，P95 ≤ 200 ms。冷启动与首次部署单独记录 |
| 动画与连打 | 60 Hz 板端以接近 60 FPS 为目标，帧间隔 P95 ≤ 20 ms。背景视频、候选展开、连打和长按分别采样。完整材质超预算时复测轻量模式 |
| 资源 | 应用启用键盘后的 PSS 增量初始目标 ≤ 80 MiB，包含默认词库、索引及渲染资源能计入进程的部分。另记录 GPU 纹理估算与数据目录大小 |
| 稳定性 | 持续输入 30 分钟，包含快速切字段、切换输入模式、挂起恢复及词包更新，确认无重复提交、跨字段提交、崩溃及单调内存增长 |
| 隐私与联网 | 默认离线和隐私会话用抓包及存储检查验证。开启云词包后，检查网络请求只有静态资源获取所需数据，密码、输入上下文、学习条目和剪贴板无写入或传输 |

主机完成 C++ 单元、输入事件集成与 Qt Quick 测试，并以 `qmllint` 检查模块。板端复测候选、触摸和图形后端行为，测试库安装至独立应用的 QML 导入与依赖解析。每次发布记录依赖版本、已验证的平台、测试结果和上一个可用词包或部署版本。

## M0 起步配置

下列命令用于项目具备 CMake 入口后。主机 Qt 工具需要其前缀内的 ICU 70 库。已用同样的构建参数在临时目录中构建 SDK 自带的 `qt6-demo`，分别生成 x86-64 和 AArch64 可执行文件。

```bash
rk_sdk="$HOME/rk3568"
rk_qt_host="$rk_sdk/qt-host/6.12.0"
rk_qt_target="$rk_sdk/qt-arm64/6.12.0"
export LD_LIBRARY_PATH="$rk_qt_host/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"

"$rk_qt_host/bin/qt-cmake" -S . -B build/host
cmake --build build/host

"$rk_qt_target/bin/qt-cmake" -S . -B build/rk3568 \
  -DQT_CHAINLOAD_TOOLCHAIN_FILE="$rk_sdk/toolchains/rk3568-buildroot.cmake" \
  -DQT_HOST_PATH="$rk_qt_host"
cmake --build build/rk3568
```

M0 需要固化两个构建命令、单独安装目录与示例启动方式。板端运行沿用 SDK 的 Wayland 环境，先验证应用部署，再接入固件打包。测得的尺寸和图形数据用于收敛 M1 布局与材质参数。
